# Развёртывание фронтенда «Пульса бизнеса»

Фронтенд — одностраничное приложение на React + Vite, запускается локально
на `http://localhost:5173`. Данные приходят из API бэкенда, поэтому сначала
запускается бэкенд (в Docker), потом фронт.

## Что нужно

- Node.js 24 и npm 11 — на них проект проверен. Старее не берите: тестовое
  окружение jsdom 27 не поддерживает Node 18.
- Docker Desktop или Docker Engine с Compose v2 — для бэкенда.
- Свободный порт **5173**: бэкенд разрешает CORS только для него.

## 1. Запустить бэкенд

Из корня репозитория, демо-режим с синтетическими данными. Подробности — в
[docs/FRONTEND_DOCKER.md](../../docs/FRONTEND_DOCKER.md).

```bash
docker compose -p pulse-frontend-demo -f compose.frontend.yml up -d --build --wait
```

API поднимется на `http://localhost:8000`, Swagger — на
`http://localhost:8000/docs`. Если порт 8000 занят, задайте другой
(PowerShell):

```powershell
$env:BACKEND_PORT='8001'
docker compose -p pulse-frontend-demo -f compose.frontend.yml up -d --build --wait
```

Проверка: `curl http://localhost:8000/health` → `{"status":"ok"}`.

**Старая база.** Init-скрипты PostgreSQL выполняются только на пустом томе.
Если том демо-базы создан до миграций 004–006, `/ready` отвечает 503 и
`--wait` падает по таймауту. Решение — в
[docs/FRONTEND_DOCKER.md](../../docs/FRONTEND_DOCKER.md); удалять том можно
только осознанно: вместе с ним удаляются локальные данные.

## 2. Настроить окружение

```bash
cd frontend
cp .env.example .env
```

| Переменная              | Что это                                                                      |
| ----------------------- | ---------------------------------------------------------------------------- |
| `VITE_BASE_API`         | Адрес API бэкенда. Порт — тот же, что у бэкенда (8000 или 8001).             |
| `VITE_DEMO_COMPANY_IDS` | Все компании демо-стенда, через запятую.                                     |
| `VITE_DEMO_ACCOUNTS`    | Тестовые логины и их компании: `логин=ID,ID;логин2=ID`. Пусто — любой логин. |

Переменные `VITE_*` встраиваются в код при запуске dev-сервера и при сборке.
После их изменения перезапустите `npm run dev`.

## 3. Запустить фронт

```bash
npm ci
npm run dev
```

Приложение откроется на `http://localhost:5173`. Тестовые логины из
`.env.example` (пароль не проверяется — авторизации в API пока нет):

| Логин      | Компании                     |
| ---------- | ---------------------------- |
| `expert`   | DEMO-001, DEMO-002, DEMO-003 |
| `bakery`   | DEMO-001 — 2 инсайта         |
| `workshop` | DEMO-002 — 1 инсайт          |
| `empty`    | DEMO-003 — пустая лента      |

Логины показываются подсказкой на экране входа. Сессия хранится в
`sessionStorage` вкладки.

Если бэкенд недоступен, над страницей появляется плашка «Сервер Пульса не
отвечает». Когда он снова поднимется, данные перезагрузятся сами.


## Частые проблемы

- **«Сервер недоступен» или ошибка CORS.** Фронт открыт не на 5173 или в
  `VITE_BASE_API` указан не тот порт бэкенда. Порт 5173 закреплён
  (`strictPort`): если он занят, Vite не стартует, а не переезжает на 5174.
- **«Такого логина нет».** Логин не из `VITE_DEMO_ACCOUNTS` — возьмите один
  из подсказки на экране входа.
- **Вечно «Компания не выбрана».** Пустые `VITE_DEMO_COMPANY_IDS` и
  `VITE_DEMO_ACCOUNTS` — проверьте `.env` и перезапустите dev-сервер.
- **Анализ новости недоступен.** В демо-режиме модель не подключена, и экран
  анализа сообщает об этом заранее. Это не поломка.
- **Не применились изменения `tailwind.config.ts`.** Dev-сервер держит конфиг с
  момента запуска — перезапустите `npm run dev`.
- **В демо нет позиции Альфа-Банка у инсайтов.** Так и должно быть: у
  синтетических данных нет фрагментов аналитики банка.
