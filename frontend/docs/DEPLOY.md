# Развёртывание фронтенда «Пульса бизнеса»

Фронтенд — одностраничное приложение на React + Vite. Данные приходят из API
бэкенда, поэтому сначала запускается бэкенд, потом фронт.

## Что нужно

- Node.js 24 и npm 11 — на них проект проверен. Старее не берите: тестовое
  окружение jsdom 27 не поддерживает Node 18.
- Docker Desktop или Docker Engine с Compose v2 — для бэкенда.
- Свободный порт **5173**: бэкенд разрешает CORS только для него.

## 1. Запустить бэкенд

Из корня репозитория, демо-режим с синтетическими данными. Подробности — в
[docs/FRONTEND_DOCKER.md](../../docs/FRONTEND_DOCKER.md).

```bash
docker compose -p pulse-frontend-demo -f compose.frontend.yml up -d --build --wait
```

API поднимется на `http://localhost:8000`. Если порт 8000 занят, задайте
другой (PowerShell):

```powershell
$env:BACKEND_PORT='8001'
docker compose -p pulse-frontend-demo -f compose.frontend.yml up -d --build --wait
```

Проверка: `curl http://localhost:8000/health` → `{"status":"ok"}`.

## 2. Настроить окружение

```bash
cd frontend
cp .env.example .env
```

| Переменная              | Что это                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| `VITE_BASE_API`         | Адрес API бэкенда. Порт — тот же, что у бэкенда (8000 или 8001).                                |
| `VITE_DEMO_COMPANY_IDS` | Компании для переключателя в шапке, через запятую. Пока нет авторизации, список задаётся здесь. |

Переменные `VITE_*` встраиваются в код **при сборке**. После их изменения
перезапустите dev-сервер или пересоберите проект.

## 3. Запустить для разработки

```bash
npm ci
npm run dev
```

Приложение откроется на `http://localhost:5173`. Вход — любой непустой логин:
авторизации в API пока нет, сессия хранится в `sessionStorage` вкладки.

## 4. Собрать для показа

```bash
npm run build
```

Готовая статика — в `dist/`. Посмотреть сборку локально:

```bash
npm run preview
```

`preview` работает на порту 4173. Чтобы запросы к API не блокировались, этот
адрес нужно добавить в `CORS_ORIGINS` бэкенда — см. раздел «Порт и CORS» в
[docs/FRONTEND_DOCKER.md](../../docs/FRONTEND_DOCKER.md).

Для размещения `dist/` на любом веб-сервере (nginx и т. п.) нужен SPA-fallback:
все неизвестные пути отдают `index.html`, иначе прямые ссылки вроде
`/pulse/insights/1` вернут 404. Отдельного Docker-образа для фронта пока нет.

## Проверки перед коммитом

```bash
npx prettier --write src && npx tsc -b && npx tsc -p tsconfig.test.json --noEmit && npx eslint src && npx vitest run && npm run build
```

## Частые проблемы

- **«Сервер недоступен» или ошибка CORS.** Фронт открыт не на 5173 или в
  `VITE_BASE_API` указан не тот порт бэкенда. Порт 5173 закреплён
  (`strictPort`): если он занят, Vite не стартует, а не переезжает на 5174.
- **Вечно «Компания не выбрана».** Пустой `VITE_DEMO_COMPANY_IDS` — проверьте
  `.env` и перезапустите dev-сервер.
- **Анализ новости отвечает «Анализ выключен в демо».** Это нормально: в
  демо-режиме бэкенд не вызывает LLM и возвращает `AI_DISABLED_IN_DEMO`.
- **Не применились изменения `tailwind.config.ts`.** Dev-сервер держит конфиг с
  момента запуска — перезапустите `npm run dev`.
- **В демо нет позиции Альфа-Банка у инсайтов.** Так и должно быть: у
  синтетических данных нет фрагментов аналитики банка.
