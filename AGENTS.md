# Правила проекта «Пульс бизнеса»

## Git и ветки

- Для новых функциональных веток использовать `feature/<название-задачи>`.
- Не использовать префикс `codex/` без согласования.
- Не изменять `main` и чужие рабочие ветки без разрешения.
- Не выполнять push, merge и не создавать PR без отдельного подтверждения.

## Коммиты

- Делать отдельный коммит после каждого завершённого и протестированного этапа.
- Не коммитить код с падающими тестами.
- Формат сообщения: `type(scope): описание на русском языке`.
- В теле указывать краткое описание изменений и строку `Версия: vX.Y.Z`.
- Не изменять уже созданные коммиты без согласования.

## Безопасность

- Не добавлять в Git API-ключи, пароли, `.env`, реальные CSV и закрытые данные хакатона.
- Для тестов использовать синтетические данные.
- Не запускать платные LLM-запросы без отдельного разрешения.
- Не удалять Docker-тома или чужие контейнеры без разрешения.

## Архитектура

- Сохранять работающие API-контракты.
- Не менять SQL-схему и миграции без согласования с разработчиком БД.
- Не создавать таблицы автоматически через ORM.
- Разделять API, бизнес-логику и доступ к данным.
- Использовать реальные RAG-фрагменты как доказательства, не придумывать цитаты и показатели достоверности.
