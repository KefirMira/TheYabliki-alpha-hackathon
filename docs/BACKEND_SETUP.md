# Запуск AI/backend на другом компьютере

Для frontend без установки Python используйте отдельную инструкцию
[Docker demo/full](FRONTEND_DOCKER.md). В Compose demo анализ отключён,
а готовые синтетические профили и инсайты доступны сразу.

Поддерживаемая проверенная среда: Python 3.12, PostgreSQL 16. Полная установка
проверяется на Windows; Linux/macOS требуют отдельного smoke-теста бинарных пакетов.
Команды выполнять из корня репозитория. Общий FastAPI, JWT и парсер подключаются
отдельно по согласованным контрактам.

## Установка

Создать чистое окружение: `python -m venv .venv`.
В Windows Python окружения — `.venv/Scripts/python.exe`, в Linux/macOS —
`.venv/bin/python`. Далее `python` означает именно этот исполняемый файл.

```sh
python -m pip install -r backend/requirements.txt
python -m pip check
```

Скопировать `backend/.env.example` в `backend/.env` средствами своей ОС.
Заполнить DATABASE_URL, LLM_API_KEY, LLM_BASE_URL, LLM_MODEL и путь RAG.
Переменные процесса имеют приоритет над `.env`. Пароль в DSN кодировать как URL.
Ни `.env`, ни секреты не передавать в Git или переписке с логами.

PostgreSQL должен содержать схему и миграции 002/003 из инфраструктуры PR №2.
Приложение таблиц не создаёт. Запуск БД и выдача учётной записи согласуются с её
разработчиком. Нужны права чтения профиля/истории и записи результатов анализа.
Без DATABASE_URL приложение запускается, маршруты с БД отвечают 503.

## Закрытая база знаний

Получить разрешённый пакет подготовленных JSON через закрытое хранилище команды,
вне Git. Ответственный за данные передаёт версию пакета, список файлов и SHA-256;
получатель сверяет хеши (`Get-FileHash` в PowerShell или `sha256sum` в Linux).
Не публиковать сам пакет, манифест с закрытыми именами документов и PDF.

Распаковать JSON в отдельный каталог вне checkout, доступный backend только для
чтения. Указать абсолютный `RAG_KNOWLEDGE_BASE_DIR` в локальном `.env`.
В контейнере использовать read-only bind mount в этот путь. Относительный путь
считается от `backend/`, стандартный — `data/processed` (игнорируется Git).
В Git не добавлять внешнюю базу даже с `git add -f`.

Формат каждого UTF-8 JSON — объект `document` и массив `pages`:

```json
{"document":"synthetic.pdf","pages":[{"page":1,"text":"Synthetic evidence"}]}
```

Это только пример структуры. Настоящие тексты и метаданные передаются владельцем
данных. Фрагменты строятся существующим chunk_service при чтении. Пустой каталог,
повреждённый JSON или отсутствие текста делают RAG неготовым. Для согласованного
обновления переключать каталог пакета и перезапускать процесс.

Готовые JSON позволяют запускать анализ без PDF и Tesseract. Для подготовки PDF
отдельно установить системный Tesseract и языки `rus`, `eng`, проверить
`tesseract --list-langs`. По умолчанию используется PATH; нестандартный исполняемый
файл задаётся `TESSERACT_CMD`, языки — `TESSERACT_LANGUAGES`. Путь с пробелами
передаётся целиком, без дополнительных кавычек внутри значения.

## Запуск и диагностика

```sh
python -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

`GET /health` сохраняет ответ `{"status":"ok"}` — процесс жив.
`GET /ready` возвращает 200 только при наличии непустой корректной RAG-базы,
трёх настроек LLM и доступности всех 13 таблиц PostgreSQL, иначе 503.
Ответ: `status` и булевы `checks.rag`, `checks.llm_config`, `checks.database`.
Проверка не делает LLM-запросов и не раскрывает DSN/пути/ключи.
Она не доказывает валидность ключа, доступность провайдера, наличие всех ограничений
БД или прав на запись; это проверяют отдельно без платного запроса.
OCR не является условием готовности сервиса с подготовленной RAG-базой.
Swagger доступен на `/docs`. Без отдельного разрешения не вызывать анализ с
настоящим ключом даже для smoke-теста. Для общего приложения необходимо включить
роутеры и database_lifespan (либо эквивалентную инициализацию company_sessions)
в общий lifespan; префикс `/api` уже включён в маршруты. JWT и CORS централизует
команда общего API. Текущий импорт поддерживает показанный `--app-dir backend`.

## Безопасные тесты

```sh
python -m pip install -r backend/requirements-profile-tests.txt
python -m pytest
```

Корневой pytest.ini выбирает только backend/tests; корневой conftest дополнительно
исключает старые backend/test_*.py при обходе каталогов. Эти старые файлы — ручные
скрипты, некоторые вызывают LLM на верхнем уровне: не запускать их явно и не
импортировать. В backend/tests отключается dotenv, удаляются LLM-переменные и
блокируется реальный SDK. Интеграционные тесты без отдельной БД пропускаются.

Полный изолированный прогон из PowerShell после подготовки корневой `.venv`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/tests/run-profile-tests.ps1 -DatabaseRoot '<отдельный-checkout-БД>/database'
```

Нужны Docker Compose и инфраструктура PR №2 в отдельном checkout. Скрипт создаёт
свой проект с синтетическими данными, останавливает только его контейнер,
сохраняет том. Он не загружает реальные CSV. Не удалять чужие контейнеры/тома.
На Linux/macOS unit/API тесты запускаются указанным Python; полный PowerShell
runner пока проверен на Windows.
