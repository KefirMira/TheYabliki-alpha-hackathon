# HTTP API анализа компании — v1.7.1

`POST /api/companies/{source_id}/analyses` выполняется синхронно. Компания загружается из PostgreSQL по source_id; профиль из тела запроса не принимается. Существующий `/api/analyze-company` сохраняет прежний контракт и поведение.

## Запрос

```json
{
  "news": {
    "title": "Синтетическая новость",
    "text": "Текст синтетической новости"
  }
}
```

title необязателен (1–500 символов), text обязателен (1–100000 символов). Пустые/пробельные строки и неизвестные поля отклоняются. Исходный текст сохраняется без удаления пробелов или переносов. Без title используется технический заголовок из первых 120 символов нормализованного текста, а не сгенерированный факт.

## Успех

201 Created возвращается только после commit всех данных:

```json
{
  "run_id": 42,
  "insight_id": 51,
  "news_id": 36,
  "status": "COMPLETED",
  "company_id": "SYNTH-COMPANY-A",
  "analysis": {
    "company_id": "SYNTH-COMPANY-A",
    "news": "Текст синтетической новости",
    "relevance": "high",
    "summary": "Условный синтетический результат",
    "risks": [],
    "opportunities": [],
    "recommendations": [],
    "sources": [{"id": 1, "document": "synthetic.pdf", "page": 1, "score": 0.42}],
    "validation": {"passed": true, "warnings": []}
  }
}
```

Числа и текст примера условные. Score источника — TF-IDF-оценка поиска, не confidence. Тексты доказательств и точность дат сохраняются в БД (см. ANALYSIS_PERSISTENCE.md); публичный analysis использует прежнюю схему без добавления выдуманных оценок.

## Ошибки

| HTTP | detail.code | Значение |
|---|---|---|
| 422 | стандартный ответ FastAPI | Неверная структура/пустой текст; AI не вызывается |
| 404 | COMPANY_NOT_FOUND | Компания не найдена; запуск не создаётся |
| 503 | DATABASE_UNAVAILABLE | БД не настроена/недоступна до создания запуска |
| 502 | AI_ANALYSIS_FAILED | Ошибка AI, некорректный результат или отсутствие контекста; FAILED записан |
| 503 | ANALYSIS_STORAGE_FAILED | Сохранение результата откатилось; FAILED записан |
| 503 | RUN_STATUS_UNCERTAIN | Не удалось подтвердить финальный статус; нужна сверка БД |

После создания запуска detail содержит run_id. Пароли, DSN и внутренние сообщения провайдера/драйвера не возвращаются. RUN_STATUS_UNCERTAIN не является утверждением, что запуск обязательно FAILED или обязательно RUNNING.

## Проверки и подмена AI

Обычный код использует существующие AI/RAG через отложенный импорт; реальные LLM-вызовы в тестах заблокированы.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File backend/tests/run-profile-tests.ps1 -DatabaseRoot <checkout-PR-2>/database
```

## Ограничения

Идемпотентность, авторизация, очередь задач, чтение истории и восстановление зависших RUNNING не входят в этот этап. Автоматический повтор POST может создать второй анализ и второй LLM-вызов; до согласования ключа идемпотентности фронтенд не должен повторять запрос автоматически. Схема PR №2 не изменена и не включена повторно. Файлы инфраструктуры берутся из отдельного checkout через DatabaseRoot.
