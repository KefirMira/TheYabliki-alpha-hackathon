# Сохранение анализа — v1.7.0

Схема PostgreSQL PR №2 используется без изменений через отдельный checkout и параметр DatabaseRoot. Файлы БД повторно в коммит не включаются.

## Транзакции

CompanyAnalysisService принимает фабрику async-сессий и подставляемый AI-анализатор.

1. Первая транзакция читает компанию по source_id и создаёт ручную новость и RUNNING-запуск. При неизвестной компании ничего не создаётся.
2. Сессия закрывается. AI вызывается без открытого соединения или транзакции БД.
3. Новая транзакция записывает company_news_analyses, все insight_evidence и COMPLETED. Частичный результат никогда не фиксируется отдельно от доказательств.
4. При исключении или отмене задачи незавершённая транзакция откатывается, затем отдельная транзакция записывает FAILED. В error_message сохраняется технический код, а не секреты или ответ провайдера.
5. Если записать FAILED тоже не удалось, возвращается RunStatusUncertain с run_id и кодом RUN_STATUS_UNCERTAIN. Сервис не утверждает, что статус сохранён.

SQL-репозитории используют только существующие таблицы. Автоматического DDL нет. Пустые/отсутствующие оценки confidence_score, relevance_score, impact_level и evidence_strength не вычисляются.

## Настоящие RAG-доказательства

Старый analyze_for_company возвращает прежнюю публичную структуру. Новая внутренняя функция analyze_for_company_with_evidence возвращает PersistableAnalysis: старый результат плюс фрагменты и модель.
RAG с include_evidence=True копирует исходный текст именно тех фрагментов, которые использовал текущий LLM-вызов. Повторный поиск и генерация цитат не используются. Режим по умолчанию сохраняет старые поля ответа; /api/analyze-company не изменён.

В evidence сохраняются исходный текст, документ, страница и chunk_id. В source_snapshot сохраняются локальный ID источника, документ, страница, chunk_id, score и исходная строка date.
Точная дата YYYY-MM-DD дополнительно сохраняется в document_date. Для даты YYYY-MM или YYYY поле DATE остаётся NULL, исходная точность сохраняется в snapshot. День не придумывается. ID источника в ответе не считается внутренним ID evidence или information_sources.
PersistableAnalysis проверяет соответствие всех ссылок источников полученным фрагментам; сервис проверяет совпадение company_id и текста новости со входом.

## Ограничения

- Зависание/аварийное завершение процесса может оставить RUNNING; нужна отдельная процедура сверки зависших запусков.
- Недоступная БД не позволяет гарантированно записать FAILED: наружу возвращается неопределённость статуса, а не ложное подтверждение.
- В схеме нет прямой ссылки analysis_runs → news_articles: неуспешный запуск не связан с новостью через результат. Миграция для такой истории — отдельное согласование с владельцем БД.
- Идемпотентность, снимок профиля, очередь задач, авторизация и полный CSV-импорт не входят в этап. Повторный запуск создаёт новую новость и новый run.
- validation.passed=false — предупреждение качества, а не технический сбой: такой результат сохраняется COMPLETED с предупреждениями.
- Существующий AI-профиль использует float; API профиля сохраняет Decimal как прежде.
