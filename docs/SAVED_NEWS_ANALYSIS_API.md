# Анализ сохранённой новости: v1.15.0

Обновление v1.20.0: [контекст компании и платёжной структуры](COMPANY_AI_CONTEXT.md)
подготавливается перед новым анализом. Стандартный внешний AI получает 503
`COMPANY_CONTEXT_EXTERNAL_TRANSFER_BLOCKED` без вызова шлюза, claim откатывается.
Повтор COMPLETED по-прежнему возвращает 200 с сохранённым результатом без AI.
Контекст доступен доверенному локальному fake-анализатору; для реального применения
нужно отдельное решение об обработке данных.

`POST /api/companies/{source_id}/news/{news_id}/analyses`

Запускает персонализированный анализ существующей news_articles. source_id —
внешний идентификатор компании, news_id — положительный BIGINT ID новости.
Тело запроса не требуется; текст и заголовок из запроса не используются.
Получить news_id можно из POST /api/news, см. NEWS_INGESTION_API.md.

## Условия

Компания и новость должны существовать. Текст новости должен быть непустым
и длиной не более 100000 символов, как при ingestion. Проверка не обрезает и
не нормализует текст. Старые записи SQL с NULL/пустым/слишком длинным content
отклоняются до создания запуска. Новость может быть MANUAL или EXTERNAL.
Для настоящего AI нужны AI_MODE=full, LLM-конфигурация и разрешённый RAG-корпус.
Вызов может быть платным — требуется отдельное разрешение.

## Результат и ошибки

201, существующая схема CreatedCompanyAnalysis:

```json
{
  "run_id": 10,
  "insight_id": 20,
  "news_id": 42,
  "status": "COMPLETED",
  "company_id": "DEMO-001",
  "analysis": {
    "company_id": "DEMO-001",
    "news": "Exact stored news text",
    "relevance": "unknown",
    "summary": "Synthetic example, not an actual AI result",
    "risks": [],
    "opportunities": [],
    "recommendations": [],
    "sources": [{"id": 1, "document": "synthetic.txt", "page": 1, "score": 0.0}],
    "validation": {"passed": false, "warnings": ["Synthetic response example"]}
  }
}
```

Значения примера вымышленные. Retrieval score не является confidence.
В рабочем ответе sources/evidence берутся из фактического RAG, не из этого примера.

| HTTP | detail.code | Поведение |
|---|---|---|
| 404 | COMPANY_NOT_FOUND | Компания отсутствует; запуск не создаётся |
| 404 | NEWS_NOT_FOUND | Новость отсутствует; запуск не создаётся |
| 422 | NEWS_CONTENT_UNAVAILABLE | Непригодный сохранённый текст; запуск не создаётся |
| 422 | стандартный validation error | Некорректный path ID |
| 502 | AI_ANALYSIS_FAILED | Ошибка AI/валидации результата, запуск FAILED при доступной БД |
| 503 | ANALYSIS_STORAGE_FAILED | Запись результата/evidence откатилась; запуск FAILED при доступной БД |
| 503 | RUN_STATUS_UNCERTAIN | Не удалось записать FAILED; run_id возвращается, успех не заявляется |
| 503 | DATABASE_UNAVAILABLE | Ошибка подключения/начальной транзакции |
| 503 | AI_DISABLED_IN_DEMO | Demo запрещает анализ до выполнения сервиса |

Если отсутствуют оба объекта, сначала проверяется компания. Формат ошибок
и результата общего pipeline сохранён для старого ручного POST.

## Транзакции и совместное использование новости

CompanyAnalysisService.analyze_saved() в короткой транзакции читает компанию
и существующую новость, проверяет текст, создаёт отдельный RUNNING. Затем сессия
закрывается. Общий _execute() вызывает AI без открытой DB-сессии и сохраняет
результат/evidence вместе со статусом COMPLETED в новой атомарной транзакции.
Ошибки используют тот же FAILED/rollback путь, что ручной анализ.

Для двух компаний передаётся один и тот же news_id в двух отдельных запросах.
Получаются разные run_id и insight_id, общий news_id. Сбой одной компании не
откатывает успешный результат другой. INSERT/UPDATE news_articles не выполняются:
сохраняются исходный текст, URL, источник, даты, хеш и прочие метаданные.

Результаты доступны через существующие GET ленты/карточки компании; незавершённые
и FAILED-запуски в успешную историю не попадают. Чужие карточки отвечают 404.

## Безопасная проверка

Из Docker demo реальный AI по-прежнему недоступен: все пять POST анализа
отвечают AI_DISABLED_IN_DEMO, включая новый маршрут. Docker smoke проверяет
эту блокировку и OpenAPI. Успешный анализ, ошибки и две компании проверяются
автотестами с подставным анализатором на изолированной PostgreSQL, без SDK LLM.

Полный прогон: backend/tests/run-profile-tests.ps1 с текущим DatabaseRoot.
v1.15.0 требует миграцию 005 поверх существующей схемы.

## Ограничения

Защита по паре сохранённой новости добавлена в v1.15.0, см. ниже. Автоматического retry нет. Нет очереди, JWT и публичного API статуса запуска; ограничьте внешний доступ. Новая попытка связана с новостью через news_analysis_jobs/news_analysis_attempts; старые RUNNING/FAILED без такой связи требуют отдельной проверки. Другие писатели БД должны соблюдать неизменяемость уже проанализированных публикаций.


## Защита повторов v1.15.0

Первая успешная попытка: 201. Повтор COMPLETED: **200 с тем же CreatedCompanyAnalysis** из сохранённого payload, без AI. RUNNING: **409 ANALYSIS_ALREADY_RUNNING**; просроченный RUNNING: 409 ANALYSIS_REVIEW_REQUIRED. FAILED: 409 ANALYSIS_RETRY_REQUIRED, пока оператор не разрешит повтор. Максимум две попытки на пару, затем ANALYSIS_ATTEMPT_LIMIT_REACHED. Сохраняйте обработку 404/422/502/503. 409 использует существующий формат detail.code/message/run_id.

Claim фиксируется PostgreSQL до AI. На время AI session закрыта. На защищённом пути SDK max_retries=0, timeout=120 секунд, общий asyncio timeout=150 секунд. Deadline попытки 180 секунд — сигнал для проверки, а не автоматического retry. Ошибка сети, тайм-аут или ошибка хранения не разрешает повтор самостоятельно. Demo по-прежнему блокирует POST до платных операций.

Миграция 005 обязательна. Старые API ручного анализа сохраняют прежнее поведение; защита распространяется на конкретную сохранённую пару, а не на совпадение текстов разных новостей. При неразобранной истории возвращается диагностический 409, а не новый платный запрос.
