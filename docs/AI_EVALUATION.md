# Безопасная оценка DeepSeek + RAG — v1.18.0

Это отдельный локальный инструмент, не API и не автоматический анализ.
По умолчанию используется fake AI. PostgreSQL, RSS, frontend и миграции не участвуют.
Инструмент не меняет production-промпты, не оптимизирует их и не оценивает
достоверность по факту прохождения JSON-валидации.

## Подготовка и проверенный корпус

Команды ниже выполнять из корня репозитория, с активированным Python 3.12
окружением backend и установленными зависимостями backend/requirements.txt.
В проверенной рабочей копии полные RAG/PDF-зависимости доступны в
`.venv-portability`; основное `.venv` не содержит numpy и не подходит для этой проверки.

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
python -m evaluation --list
python -m evaluation --synthetic-rag
python -m evaluation --rag-dir data/processed
```

Пути RAG относительно `backend/`, либо абсолютные. Fake не читает `.env` и не
импортирует SDK: для перенесённого корпуса передать `--rag-dir`, либо установить
`RAG_KNOWLEDGE_BASE_DIR` в окружении. `--synthetic-rag` работает без закрытого корпуса
и ключа. Пустой/повреждённый корпус даёт явную ошибку, не заменяется синтетическим
автоматически. Отсутствие найденных фрагментов не вызывает AI.

Проверка 24 октября 2026: 9 PDF открываются, 64 страницы, текстовый слой отсутствует
на всех страницах. RAG загружает 9 ранее подготовленных OCR-JSON и 222 фрагмента
с текстом, документом и страницей. Наличие текста после OCR не подтверждает
правильность распознавания. OCR заново не запускался. Закрытый корпус не включён
в Git и его наличие на другом компьютере нужно обеспечить отдельно.

## Сценарии

Встроены 8 полностью вымышленных сценариев и профилей с неизвестной кредитной
экспозицией: ставка для топливной компании, золото для добывающей, нерелевантный
спортивный сюжет для IT, неоднозначное название «Мир», инфляция для розницы,
историческая металлургия, экспорт при неизвестной экспортной деятельности,
нехватка контекста для локальной новости о животных. `review_expectation` —
критерий ручной проверки, не эталонный финансовый ответ.

Оценка использует существующий TF-IDF top_k=3, CompanyProfile, JSON-парсер и
эвристическую validation. Снимки текстов промптов проверяются по хешам двух
production-файлов; несовпадение блокирует запуск. Тесты сравнивают весь запрос
и evidence с production RAG при подставном SDK. Новые лимиты max_tokens/timeout
относятся только к оценочному клиенту, не меняют production API.

## Реальные запросы: только после отдельного разрешения

### Один синтетический тест через шлюз организаторов

По официальной инструкции, параметры которой предоставлены владельцем проекта:
основной Base URL `https://changellenge.up.railway.app/v1`, резервный
`https://api.alfahack-gateway26.ru/v1`, OpenAI-compatible API, модель
`deepseek/deepseek-v4.1-flash`. Квота — **500 рублей в день на общий ключ команды**,
сброс **03:00 МСК**. Это сведения об общем лимите, не тариф одного запроса и
не подтверждение текущего остатка. Условия хранения запросов здесь не установлены.

Для этой квоты добавлен отдельный `--organizer-gateway`: USD-тарифы и бюджет
не требуются и не допускаются. Плановая/итоговая USD-стоимость и известная часть
стоимости имеют `null`, а не фиктивный ноль; сохраняются фактические usage при
наличии. Локальные ограничения **не гарантируют денежный предел списания**.
Остаток квоты инструмент не проверяет, другие участники расходуют тот же ключ.

Режим допускает исключительно `--real --synthetic-rag --scenario macro-rate`,
один запрос, входной плановый предел до 16000, выход до 1000 токенов и максимум
60 секунд на запрос/серию. Другие сценарии, `--rag-dir` и USD-флаги отвергаются.
Base URL проверяется по двум точным адресам, модель — по точному идентификатору,
а host требует отдельного разрешения. Переключение на резервный адрес только
вручную после проверки неизвестного исхода и нового разрешения; автоматического
fallback, повторов SDK, повторной генерации или автоматического resume нет.

Только локальный план, без SDK-клиента и сетевого запроса к модели:

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
& .\.venv-portability\Scripts\python.exe -B -m evaluation `
  --real --plan --organizer-gateway --synthetic-rag --scenario macro-rate `
  --max-requests 1 --max-input-tokens 6000 --max-output-tokens 1000 `
  --request-seconds 60 --total-seconds 60 `
  --allow-provider-host changellenge.up.railway.app
```

Настоящий запуск **только после отдельного разрешения**, из корня репозитория:

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
$env:LLM_BASE_URL = 'https://changellenge.up.railway.app/v1'
$env:LLM_MODEL = 'deepseek/deepseek-v4.1-flash'
& .\.venv-portability\Scripts\python.exe -B -m evaluation `
  --real --organizer-gateway --synthetic-rag --scenario macro-rate `
  --max-requests 1 --max-input-tokens 6000 --max-output-tokens 1000 `
  --request-seconds 60 --total-seconds 60 `
  --allow-provider-host changellenge.up.railway.app `
  --allow-rag-transfer --acknowledge-unknown-cost
```

Путь Python относится к проверенной рабочей копии; на другом компьютере использовать
своё окружение с зависимостями backend. Ключ читается из окружения или `backend/.env`,
не из аргумента. `--acknowledge-unknown-cost` подтверждает понимание неизвестной цены
и общей квоты; наличие флага в примере не является разрешением запустить команду.
При `AI_MODE=demo` реальный режим по-прежнему запрещён.

При подготовке macro-rate содержимое messages занимает 4298 байт UTF-8,
JSON-тело примерно 4,5 КБ; плановая оценка входа 4810 токенов (байты + 512),
не точный токенизатор. Максимум выхода задаётся 1000 токенов. Ни таймер, ни
`max_tokens` не подтверждают фактическое списание/обработку шлюзом.
Только вымышленный профиль/новость и встроенный synthetic-evaluation.txt;
реальный RAG, PDF, CSV, PostgreSQL и DB-контекст не загружаются.
Это отдельный CLI, а не production API: COMPANY_CONTEXT_EXTERNAL_TRANSFER_BLOCKED
не отключается и не обходится. Ключ передаётся только как авторизация SDK, не в messages.

HTTP-ошибка шлюза с сообщением `Budget has been exceeded` сохраняется как
`BUDGET_EXCEEDED_NO_RETRY`, код `PROVIDER_BUDGET_EXCEEDED` возвращается в
`error_codes` итогового вывода/summary. Исходное сообщение провайдера, заголовки
и ключ не сохраняются. Любая ошибка останавливает запуск; тайм-аут/сетевая ошибка
означают неизвестный исход, а не гарантированное отсутствие списания.
Нужно изучить intent/result/summary и проверить квоту у организаторов перед
любым ручным повтором. Техническая проверка JSON не доказывает качество ответа.

### Режим с подтверждёнными USD-тарифами

В этой версии реальные запросы **не выполнялись**. Наличие ключа не является
разрешением на запросы. Следующие команды подготовлены для будущего запуска
после подтверждения владельца ключа и права передать выбранные фрагменты.

Реальный режим читает `backend/.env`, затем накладывает значения окружения.
Ключ не передаётся аргументом и не записывается в отчёты. Конфигурация текущей
копии использует модель `deepseek/deepseek-v4.1-flash` через шлюз
`changellenge.up.railway.app`, а не прямой официальный API DeepSeek.
Тариф шлюза, единица списания, комиссии и передача закрытых материалов требуют
подтверждения. Публичный прайс DeepSeek не является тарифом этого шлюза.
Никаких запросов к шлюзу для определения тарифа инструмент не делает.

Для обычного запуска без `--organizer-gateway` обязательны явные тарифы USD/1M,
бюджет и разрешённый host. Без этих значений --real блокируется.
В AI_MODE=demo реальный режим запрещён.
URL должен быть HTTPS, без username/password, query/fragment, с обычным TLS-портом.
Переадресации и proxy-настройки окружения отключены; TLS-проверка сохранена.

```powershell
$inRate = Read-Host 'Подтверждённый тариф шлюза за 1M входных токенов, USD'
$outRate = Read-Host 'Подтверждённый тариф за 1M выходных токенов, USD'

# Только локальный план, без SDK-запроса, ключ не выводится:
python -m evaluation --real --plan --scenario macro-rate --max-requests 1 --allow-provider-host changellenge.up.railway.app --input-usd-per-million $inRate --output-usd-per-million $outRate --budget-usd 0.05

# ОДИН платный запрос — выполнять только после отдельного подтверждения:
python -m evaluation --real --scenario macro-rate --max-requests 1 --allow-rag-transfer --allow-provider-host changellenge.up.railway.app --input-usd-per-million $inRate --output-usd-per-million $outRate --budget-usd 0.05

# Серия из восьми — требует отдельного разрешения на всю серию и бюджет:
python -m evaluation --real --max-requests 8 --total-seconds 600 --allow-rag-transfer --allow-provider-host changellenge.up.railway.app --input-usd-per-million $inRate --output-usd-per-million $outRate --budget-usd 0.20
```

Бюджеты в командах — ограничения, не обещание, что подтверждённый тариф в них
поместится: при превышении плана инструмент откажет до первого запроса.
Сценарии можно выбирать повторяющимся `--scenario`; один сценарий не дублируется.
`--allow-rag-transfer` подтверждает разрешение отправить именно выбранные тексты
разрешённому шлюзу. Переносить ключ или закрытый корпус в Git нельзя.

## Ограничения расходов и неопределённые исходы

- По умолчанию максимум **1 реальный запрос**, максимум разрешено 10 за запуск.
- Вход: плановый лимит 16000, максимум 64000. Используется консервативная оценка
  по UTF-8 bytes + 512, не точный токенизатор провайдера. При превышении — отказ,
  промпты/фрагменты не обрезаются для сокрытия превышения.
- Выход: `max_tokens=1000` по умолчанию, максимум 4000. Малого лимита может не хватить
  на JSON; `finish_reason=length` сохраняется как техническая проблема.
- Один запрос: 60 секунд по умолчанию, максимум 120. Серия: 180 секунд по умолчанию,
  максимум 900 (время исполнения запросов и сохранения, после подготовки корпуса).
- SDK max_retries=0; никакого repair JSON, повторной генерации, fallback-модели,
  инструментальных вызовов, параллельных запросов или автоматического resume.
- Превышение бюджета/числа запросов плана блокирует всю серию до отправки.
  Ошибка, тайм-аут, отсутствие usage или выход за оценочную границу останавливают
  последующие запросы. Ответы с невалидным JSON сохраняются, но не исправляются AI.
- Перед отправкой fsync-сохраняется `.intent.json`. При падении процесса или
  тайм-ауте провайдер всё ещё мог обработать и тарифицировать запрос. Не повторять
  команду автоматически; сначала проверить отчёт, логи/биллинг шлюза и получить
  отдельное решение. Файлы намерения сохраняются и при успешном ответе — проверять
  итоговый JSON рядом с ними.
- Флаги ограничивают один процесс. Несколько независимых запусков суммируют расходы.

Формула USD: `(input_tokens × input_rate + output_tokens × output_rate) / 1_000_000`.
При лимитах 16000/1000 один запрос оценивается не более чем
`0.016 × input_rate + 0.001 × output_rate`, восемь — в восемь раз больше.
**Только пример:** при условных тарифах $1/$2 — $0.018 за один и $0.144 за восемь.
Эти числа не являются тарифом настроенного шлюза.

Кэш-скидки не предполагаются. Unknown reasoning/usage, комиссии и игнорирование
лимита шлюзом могут сделать локальный прогноз неверным. Жёсткая гарантия списания
возможна только с подтверждённым биллингом и лимитом со стороны провайдера.
При неизвестном исходе итоговая стоимость `null`, известная часть — отдельно;
неизвестная стоимость не представляется как нулевая.

## Как читать результаты

Каждый запуск создаёт отдельную папку `backend/evaluation-results/<UTC>-<UUID>/`,
исключённую из Git. Другой output-dir CLI не разрешает. Существующие результаты
не перезаписываются. На Windows действуют унаследованные ACL каталога пользователя;
хранить каталог в доступной только команде/владельцу области.

- `manifest.json`: режим fake/real, лимиты и план стоимости, модель/host без ключа,
  хеши OCR-JSON, исходных промптов и выбранного контекста.
- `<scenario>.json`: синтетический профиль и новость, точные отправленные messages,
  реальные выбранные RAG-фрагменты с документом/страницей/chunk_id/датой/score,
  сырой ответ, finish_reason, время, usage и технические проверки.
- `<scenario>.intent.json`: намерение отправки; после сбоя outcome может быть неизвестен.
- `summary.json`: количество попыток, статусы, известные расходы и полнота биллинга.
- `manual-review.tsv`: таблица ручной проверки; fake-ответы явно помечены.

Таблицу можно открыть в редакторе или Excel как UTF-8 с разделителем TAB.
Каждый из пяти критериев оценивать **0–2**: 0 — существенная ошибка, 1 — частично,
2 — удовлетворительно; пусто — не проверено. Заполнить reviewer и notes.

| Критерий | Что проверять вручную |
|---|---|
| factual_accuracy | Каждую цифру, утверждение, дату и цитату по оригинальному PDF; учесть OCR-ошибки |
| company_alignment | Вывод следует из доступного профиля; нет выдуманного экспорта, долга, имени |
| recommendation_quality | Конкретные, условные при недостатке данных действия, без неподтверждённых гарантий |
| source_correctness | Указанный документ/страница подтверждают тезис, а не просто найдены TF-IDF |
| facts_vs_assumptions | Факт, исторический контекст, предположение и прогноз явно различены |

`schema_valid`, наличие номера источника и отсутствие эвристических предупреждений
не подтверждают фактическую точность. Проверка citation_ids_valid проверяет лишь,
что номера входят в выбранный набор, а не что источник доказывает утверждение.
Поисковый score — не confidence. Для отсутствующих дат не придумывается точность.
Fake нужен только для проверки работы инструмента, не для оценки качества DeepSeek.

Отчёты содержат закрытые выдержки. Не прикладывать их к публичному PR, не добавлять
через git add -f и не отправлять третьим сторонам без отдельного разрешения.

## Безопасные проверки подготовки

24 октября 2026: 32 теста оценочного инструмента и полный прогон **520 passed,
0 skipped**, включая изолированную PostgreSQL и сохранность синтетических данных.
SDK и внешняя сеть блокировались, реальные LLM-запросы не выполнялись.
CLI отдельно проверен на восьми сценариях с fake AI и синтетическим корпусом,
затем с fake AI и доступными 222 локальными фрагментами. Обе серии успешны.
Docker smoke приложения отдельно не повторялся: Docker и production backend
в этом изменении не менялись. Использованы отдельные новые тестовые тома,
существующая внешняя сеть; созданные контейнеры остановлены без удаления ресурсов.
