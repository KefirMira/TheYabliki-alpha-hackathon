# Приём внешних новостей: v1.11.0

`POST /api/news` сохраняет публикацию без LLM и без создания analysis_runs.
Требуется PostgreSQL с schema.sql и миграциями 002/003/004. Backend не создаёт
индексы/таблицы автоматически. Старые API анализа и формат инсайтов сохранены.

## Запрос

```json
{
  "title": "Synthetic publication",
  "content": "Entirely invented parser example.",
  "url": "HTTPS://EXAMPLE.INVALID/News/A?article=7&utm_source=test#part",
  "source_name": "synthetic-demo",
  "source_id": "SYNTH-PARSER-001",
  "published_at": "2026-01-01T12:00:00+03:00",
  "language": "ru"
}
```

Обязательны title (1–500 символов) и content (1–100000 символов), не только
whitespace и без NUL. Хотя SQL допускает NULL content, ingestion требует текст,
готовый к последующему анализу. Текст и заголовок не нормализуются и не обрезаются.

Остальные поля необязательны и допускают NULL:

| Поле | Проверка |
|---|---|
| url | До 2048 символов, явный HTTP/HTTPS и hostname; без credentials, control/пробелов, backslash и некорректного percent encoding |
| source_name | 1–100 символов lowercase ASCII `[a-z0-9._-]`; стабильный технический ID источника |
| source_id | 1–500 символов, без крайних ASCII whitespace и NUL, регистр сохраняется |
| published_at | ISO 8601 с явным timezone; naive datetime и числовой timestamp отклоняются |
| language | 1–10 символов, не пустая/whitespace строка; автоматического определения и проверки ISO-кода нет |

Неизвестные поля запрещены. Пустую метаинформацию передавать как NULL или не
передавать. source_id сохраняет внутренние пробелы и Unicode; крайние Unicode
whitespace вне ASCII-группы пока не запрещены, как и в 004.

## Канонический URL

Scheme и hostname приводятся к lowercase, international hostname — к IDNA;
fragment удаляется. Tracking удаляется без учёта регистра имени:
`utm_*`, `gclid`, `dclid`, `fbclid`, `msclkid`, `yclid`, `_openstat`, `mc_cid`, `mc_eid`.
Percent-encoded имена tracking-параметров тоже распознаются.

Значимые query-параметры, их порядок, повторы и percent encoding сохраняются.
Регистр path, HTTP/HTTPS, www, завершающий слеш и явный порт не объединяются.
Backend не скачивает URL, не следует redirects и не ищет похожие тексты.
Старые неканонические URL не переписываются: их обработка требует отдельного
согласования, иначе возможны дубликаты между старой и новой загрузкой.

## Ответы

201 — создана новая EXTERNAL-новость. Пример:

```json
{
  "news_id": 42,
  "created": true,
  "duplicate": false,
  "diagnostics": [],
  "news": {
    "title": "Synthetic publication",
    "url": "https://example.invalid/News/A?article=7",
    "source_name": "synthetic-demo",
    "source_id": "SYNTH-PARSER-001",
    "published_at": "2026-01-01T09:00:00Z",
    "language": "ru",
    "input_kind": "EXTERNAL"
  }
}
```

200 — дубликат: created=false, duplicate=true, news_id и news относятся к
СОХРАНЁННОЙ записи. Ни текст, ни URL, ни метаданные не перезаписываются.
Полный content в ответ не возвращается. diagnostics может содержать:

- URL_MISMATCH — полная пара совпала, переданный URL отличается;
- SOURCE_IDENTITY_MISMATCH — переданные source_name/source_id отличаются
  либо URL принадлежит MANUAL-записи; новая пара не становится алиасом.
  Неполная пара может дать диагностику, но не используется для поиска дубликатов;
- CONTENT_MISMATCH — текст отличается;
- TITLE_MISMATCH — заголовок отличается;
- METADATA_MISMATCH — переданные published_at или language отличаются.

Не переданные метаданные не считаются просьбой очистить сохранённые значения.
Пара учитывается только при наличии обоих компонентов. Если нет ни URL, ни
полной пары, каждый запрос создаёт отдельную новость, даже с одинаковым текстом.
SHA-256 content сохраняется для диагностики, не используется для дедупликации.

409 NEWS_IDENTITY_CONFLICT — пара указывает на одну строку, URL на другую;
ничего не изменяется. Автоматически сливать записи или повторять с заменой ID нельзя.
422 — ошибка входной схемы. 503 DATABASE_UNAVAILABLE — ошибка БД без раскрытия DSN.
503 NEWS_INGESTION_RETRY — после конкурирующего INSERT запись не удалось найти.

Гонки защищены UNIQUE(url) и индексом 004. INSERT ON CONFLICT DO NOTHING не
перезаписывает запись. После конфликта отдельный SQL-запрос при READ COMMITTED
ищет обе идентичности заново. На запрос максимум один INSERT и одно повторное
чтение: бесконечного retry нет. При 503 парсер может повторить запрос с задержкой
и ограничением числа попыток; при отсутствии надёжного ключа повтор может создать
новую строку. Не путать этот приём с платным POST анализа, для которого автоматический
retry по-прежнему недопустим.

## Demo и Docker

В demo принимается только явная маркировка синтетического набора:
source_name=`synthetic-demo`, source_id начинается с `SYNTH-`, URL отсутствует
либо hostname равен `example.invalid`/его поддомену. Иначе 403
DEMO_SYNTHETIC_NEWS_ONLY до записи. Это ограничение идентификаторов, а не
автоматическая проверка содержания: отправитель обязан использовать вымышленные
тексты. Не загружать реальные новости в demo под синтетическими идентификаторами.

Из контейнера парсера в Compose: `http://backend:8000/api/news`, с хоста:
`http://localhost:8000/api/news` (либо настроенный BACKEND_PORT). Demo smoke
проверяет приём, изменённый дубликат и отклонение немаркированного ввода.
Приём не включает анализ и не отменяет запрет всех пяти AI POST в demo.

## Ограничения

JWT ещё не подключён: перед командным/внешним доступом связать маршрут с общей
авторизацией. Нет batch API, версии текста, алиасов внешних ID, очереди и
автоматического анализа. Явный запуск по news_id описан в
[SAVED_NEWS_ANALYSIS_API.md](SAVED_NEWS_ANALYSIS_API.md). Настройки collation/индексов должны
соответствовать миграции 004. Применение к общей БД требует отдельного разрешения.
