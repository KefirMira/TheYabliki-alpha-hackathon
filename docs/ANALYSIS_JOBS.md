# Защищённый анализ сохранённых новостей — v1.15.0

Область: POST /api/companies/{source_id}/news/{news_id}/analyses. Одна строка задания на пару, максимум две попытки. Статус хранится в analysis_runs; попытка содержит владельца, срок проверки, разрешение retry и исходный JSON ответа. LLM вызывается после commit claim и закрытия session. Завершение блокирует то же задание и проверяет владельца. Сохранение результата/evidence/payload/COMPLETED атомарно.

## Ответы

201 — новый результат. 200 — сохранённый COMPLETED с тем же JSON, без AI. 409 ANALYSIS_ALREADY_RUNNING — уже выполняется; ANALYSIS_REVIEW_REQUIRED — просрочено/неопределённость; ANALYSIS_RETRY_REQUIRED — FAILED без разрешения; ANALYSIS_ATTEMPT_LIMIT_REACHED — лимит; ANALYSIS_ATTEMPT_CLOSED — поздний исполнитель. Остальные 404/422/502/503 сохранены. При ошибке связи с БД нельзя считать запуск отсутствующим или FAILED без подтверждения. Повтор запроса безопасно проверяет состояние.

## Проверка зависаний и ручной retry

Публичного административного endpoint нет. Команды выполняет доверенный оператор локально из backend, с DATABASE_URL из окружения. CLI не читает .env и не импортирует AI. Не передавайте DSN как аргумент командной строки.

```powershell
cd backend
python -m analysis_admin inspect
python -m analysis_admin close --company-source-id SYNTH-COMPANY-A --news-id 1 --run-id 7 --actor operator --reason "Проверено завершение старого исполнителя и провайдера" --confirm-worker-stopped --confirm-provider-finished
python -m analysis_admin approve-retry --company-source-id SYNTH-COMPANY-A --news-id 1 --run-id 7 --actor operator --reason "Разрешена вторая попытка после проверки" --confirm-worker-stopped --confirm-provider-finished
```

inspect — read-only, до 100 просроченных RUNNING, без закрытия и перезапуска. close переводит конкретную текущую RUNNING в FAILED/REVIEW_REQUIRED. approve-retry разрешает следующую попытку только после FAILED, не запускает AI и не сбрасывает счётчик. Следующий POST создаёт новый analysis_run. Одновременные POST не создают несколько вторых попыток. Указание старого run_id отклоняется.

**Оба подтверждения являются ответственным заявлением оператора**, а не автоматическим доказательством. Сначала подтвердите прекращение старого исполнителя и удалённой обработки. Если провайдер не позволяет выяснить исход запроса, оставляйте пару заблокированной. Не используйте срок 180 секунд как автоматическое разрешение retry. Новая попытка после неопределённого запроса может привести к дополнительному списанию, даже если локальная конкурентность исключена.

В MVP все ошибки после dispatch требуют ручной проверки; автоматического retry нет. Защищённый SDK: max_retries=0, timeout=120 секунд; общий timeout=150 секунд. Невалидный AI-ответ также расходует попытку. Ограничение двух попыток не является глобальным денежным бюджетом: разные пары имеют независимые лимиты. Повторный анализ после изменения модели/профиля/корпуса не открывается автоматически.

Demo блокирует AI до сервиса. Ручной POST и legacy LLM API сохраняют прежний контракт и не получают дедупликацию по тексту. Доступ к ним и к платному POST нужно ограничить общей авторизацией до публичного развёртывания.
