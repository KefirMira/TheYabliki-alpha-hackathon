# Импорт профилей компаний — v1.19.0a

Только `df_Uid_data_hack.csv`: UTF-8 (допустим BOM), `;`, ровно 24 заголовка
в исходном порядке. Платежи и связи SYNTHETIC_F не импортируются.
Реальные файлы храните вне Git; не публикуйте их и не монтируйте в Docker demo.

Из корня backend, с установленными зависимостями backend:

```powershell
python -m company_import --file 'C:\private\df_Uid_data_hack.csv'
```

Это dry-run без подключения к PostgreSQL, даже при наличии DATABASE_URL.
Коды завершения: 0 — файл принят полностью; 2 — есть отклонённые строки;
1 — ошибка файла/формата. Отчёт содержит только количества, номера физических
строк (заголовок — строка 1), поля и коды ошибок. Он не печатает значения,
идентификаторы, суммы, пути к исходникам или DSN.

Различающиеся строки с одним SYNTHETIC_U исключаются **все**, включая корректные.
Полностью одинаковые строки дают один профиль со всеми номерами строк.
Неисправная структура записи останавливает обработку всего файла:
нельзя надёжно определить её идентификатор и границы конфликта.

Проверяются непустые обязательные поля, длина, отсутствие крайних пробелов
и управляющих символов; ОКВЭД — текстовый код, не число; выручка — конечный
неотрицательный Decimal, точно представимый NUMERIC(18,2), без округления.
Флаги допускают 0/1/0.0/1.0. Перечисления статуса, возраста, этапа развития,
численности и типа организации соответствуют проверенной выгрузке.
Названия ОКФС, отрасли, города, региона и группы — текст, не выдуманный справочник.
Пустыми могут быть ECO_MARK_LABEL, AMOUNT_WORKERS_SPARK_GRADATION, FTS_COUNTRY_NAME.
Неизвестные новые категории требуют обновления валидатора, а не молчаливого принятия.

CL_TYPE CLOSE_CLIENT преобразуется в CLOSED_CLIENT; CLIENT и PROSPECT сохраняются.
Неизвестные название, ИНН, ОГРН, год/валюта выручки и точная численность не выводятся
из CSV. Интервалы численности остаются исходными строками.

## Применение только в отдельной тестовой PostgreSQL

CLI не читает `.env` и DATABASE_URL. Применение требует отдельной переменной
COMPANY_IMPORT_DATABASE_URL, драйвера `postgresql+asyncpg`, буквального loopback
127.0.0.1 или ::1, явного порта, имени БД `test_[a-z0-9_]+` и совпадающего
`--expected-database`. Query-параметры DSN запрещены. Перед первой записью
read-only проверяется комментарий БД `pulse:isolated-company-import:v1`.
CLI не создаёт БД, не ставит этот маркер и не выполняет миграции.

Эти проверки защищают от обычной ошибки выбора окружения, но не доказывают,
что ошибочно помеченная БД или loopback-туннель не ведёт на общий сервер.
**Запрещено помечать shared/production или использовать туннели к ним.**
Для этой версии поддерживается только отдельная локальная тестовая БД.

На заранее проверенном изолированном PostgreSQL создайте новую БД, например
`test_company_import_demo`; существующую БД с этим именем не пересоздавайте.
Примените schema.sql → 002 → 003 → 004 → 005 → 006, затем установите маркер
(все команды только на собственном тестовом сервере):

```sql
COMMENT ON DATABASE test_company_import_demo IS 'pulse:isolated-company-import:v1';
```

Синтетические фикстуры не обязательны. Не копируйте demo-том и не подключайте
общую БД. Подробности изолированного тестового Compose:
[DATABASE_HANDOFF.md](DATABASE_HANDOFF.md), параметр ComposeOverride позволяет
использовать уже существующую тестовую сеть без создания новой подсети.

Из backend (значение DSN задайте локально, не публикуйте и не сохраняйте в Git):

```powershell
# COMPANY_IMPORT_DATABASE_URL должна быть установлена в текущем процессе.
python -m company_import --file 'C:\private\df_Uid_data_hack.csv' `
  --apply --confirm-isolated-import --target isolated `
  --expected-database test_company_import_demo --allow-partial
```

Без `--allow-partial` любое отклонение CSV блокирует всю запись. С ним
применяются только прошедшие проверку профили, а все строки конфликтных
идентификаторов остаются исключёнными. Код 2 после успешного применения
означает, что разрешённый частичный импорт завершён, но есть отклонения.

По умолчанию новые профили создаются, повтор того же импорта ничего не меняет.
Изменение существующих полей/исходных атрибутов или принятие ранее созданного
профиля требует дополнительного `--update-existing`. Без него конфликт
останавливает и откатывает всю транзакцию. Для обновления повторите ту же
команду с `--update-existing` после dry-run и проверки целевой БД.
Dry-run проверяет только файл, не прогнозирует конфликты с текущей БД.

Разрешено обновлять только industry, region, client_status и выручку **без года**.
Если у существующей выручки есть revenue_year, сохраняются и сумма, и год;
счётчик dated_revenue_preserved показывает расхождение с CSV. Неизвестный
год не подставляется к новой сумме. Name, ИНН/ОГРН, website, employee_count,
revenue_year, проверенные альтернативные названия и история анализов не меняются.
Новому профилю сохраняется пустой технический name: существующий API возвращает
`name=null`, `name_is_placeholder=true`, а не выдаёт SYNTHETIC_U за название.

Все 24 исходных атрибута и происхождение сохраняются в изолированном пространстве
`companies.source_data._company_profile_csv_v1`: source, текущий снимок и история
предыдущих снимков. Снимок содержит SHA-256 файла и строки, номера физических
строк, версию импортера и attributes. Остальные ключи source_data сохраняются.
Файловый путь и API-ключи не сохраняются. История содержит чувствительные
атрибуты: доступ к БД и резервным копиям должен быть ограничен.

## Проверка и ошибки

Проверьте счётчики created/updated/unchanged и rejected_rows. Для новой БД число
созданных профилей должно совпасть с eligible_profiles. Повтор того же файла
даёт unchanged без изменения строк компаний и происхождения.
Профиль доступен через существующий GET /api/companies/{source_id}; выручка
в API — десятичная строка, credit_exposure=None. Для AI переиспользуются отрасль,
регион и выручка через существующий адаптер; остальные CSV-атрибуты автоматически
в AI не передаются. Без настоящих названий, ИНН/ОГРН или проверенных альтернативных
названий CSV не обеспечивает идентификационного сопоставления с новостями.

Ошибочные строки исправляют в отдельной разрешённой версии файла, не удаляя
исходник и не выбирая произвольную конфликтующую строку. Затем снова dry-run.
Ошибка БД откатывает все изменения строк текущего запуска (последовательности
IDENTITY могут иметь пропуски). Автоматических повторов нет. При потере ответа
после commit сначала проверьте состояние; идемпотентный повтор безопасен для
того же файла и тех же настроек, новый платный анализ он не запускает.

Ограничения: нет импорта платежей/связей, удаления отсутствующих компаний,
потокового COPY, автоматического исправления CSV и подключения к общей БД.
Обработка профилей выполняется последовательно в одной транзакции; объём
85 тысяч строк потребует времени и удерживает блокировки до commit.
Нет отдельного API просмотра приватных атрибутов или истории импортов.

Тесты создают полностью синтетические CSV с теми же заголовками в pytest tmp_path.
Реальные CSV не являются фикстурами и не монтируются в тестовую PostgreSQL.

```powershell
# Из корня; для полного PG-прогона используйте подготовленное тестовое окружение.
python -m pytest backend/tests/test_company_import.py -q
powershell -NoProfile -ExecutionPolicy Bypass -File backend/tests/run-profile-tests.ps1 `
  -ComposeOverride 'C:\private\external-network.override.yml'
```
