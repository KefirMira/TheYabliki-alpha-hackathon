# Импорт профилей компаний — v1.19.0a

Только `df_Uid_data_hack.csv`: UTF-8 (допустим BOM), `;`, ровно 24 заголовка
в исходном порядке. Платежи и связи SYNTHETIC_F не импортируются.
Реальные файлы храните вне Git; не публикуйте их и не монтируйте в Docker demo.

Из корня backend, с установленными зависимостями backend:

```powershell
python -m company_import --file 'C:\private\df_Uid_data_hack.csv'
```

Это dry-run без подключения к PostgreSQL, даже при наличии DATABASE_URL.
Коды завершения: 0 — файл принят полностью; 2 — есть отклонённые строки;
1 — ошибка файла/формата. Отчёт содержит только количества, номера физических
строк (заголовок — строка 1), поля и коды ошибок. Он не печатает значения,
идентификаторы, суммы, пути к исходникам или DSN.

Различающиеся строки с одним SYNTHETIC_U исключаются **все**, включая корректные.
Полностью одинаковые строки дают один профиль со всеми номерами строк.
Неисправная структура записи останавливает обработку всего файла:
нельзя надёжно определить её идентификатор и границы конфликта.

Проверяются непустые обязательные поля, длина, отсутствие крайних пробелов
и управляющих символов; ОКВЭД — текстовый код, не число; выручка — конечный
неотрицательный Decimal, точно представимый NUMERIC(18,2), без округления.
Флаги допускают 0/1/0.0/1.0. Перечисления статуса, возраста, этапа развития,
численности и типа организации соответствуют проверенной выгрузке.
Названия ОКФС, отрасли, города, региона и группы — текст, не выдуманный справочник.
Пустыми могут быть ECO_MARK_LABEL, AMOUNT_WORKERS_SPARK_GRADATION, FTS_COUNTRY_NAME.
Неизвестные новые категории требуют обновления валидатора, а не молчаливого принятия.

CL_TYPE CLOSE_CLIENT преобразуется в CLOSED_CLIENT; CLIENT и PROSPECT сохраняются.
Неизвестные название, ИНН, ОГРН, год/валюта выручки и точная численность не выводятся
из CSV. Интервалы численности остаются исходными строками.
